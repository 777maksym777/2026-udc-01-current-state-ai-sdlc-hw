## Conventions

1. **App Router only.** All routes/UI live under `app/`. Use the special files (`layout.tsx`, `page.tsx`, `globals.css`); do not introduce a `pages/` directory.
2. **TypeScript everywhere, strict.** New code is `.ts`/`.tsx`. Keep `strict` clean — no `any` escape hatches and no new type errors.
3. **Imports via the `@/*` alias.** Use `@/...` (mapped to project root in `tsconfig.json`) for internal imports rather than long relative paths.
4. **Naming.** Components in `PascalCase`, hooks as `useX`, files matching Next.js conventions (`page.tsx`, `layout.tsx`); default-export the route component for `page`/`layout`.
5. **Styling with Tailwind utilities.** Prefer Tailwind classes in JSX; put global/base styles in `app/globals.css`. Keep components Server Components by default — add `"use client"` only when client interactivity is required.

## Guardrails

1. **Do not edit generated/build output.** Leave `.next/`, `next-env.d.ts`, `node_modules/`, and lockfile-derived files alone — `.next/` and `next-env.d.ts` are git-ignored and regenerated by the build.
2. **Do not bump or swap core dependencies** (Next.js, React, TypeScript, Tailwind) or migrate config formats without explicit approval — pinned versions here have breaking changes vs. older docs.
3. **Do not assume legacy Next.js APIs.** Per the rules block above, verify against `node_modules/next/dist/docs/` before using any Next.js API; don't reintroduce deprecated patterns.
